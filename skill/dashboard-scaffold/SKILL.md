# dashboard-scaffold

작게 시작해서 점차 커지는 대시보드 프로젝트 양식. 미리 만들어 둔 폴더는 쓰이지 않은 채 복잡도만 늘리므로, **필요해지는 순간에만** 구조를 늘린다.

## 시작 구조 (파일 5개)

```
<project>/
├── README.md              목적, 실행법, 지표 목록
├── build.py               시트 다운로드 → 집계 → data/*.json
├── index.html             대시보드 (HTML+CSS+JS 한 파일)
├── data/                  build.py 결과 (CSV는 git 제외)
└── docs/requirements.md   인터뷰 결과
```

실행은 두 줄이다: `python3 build.py`, `python3 -m http.server`.

## 만드는 방법

1. 사용자에게 구글 시트 URL을 받는다(공유가 "링크가 있는 모든 사용자"여야 내려받을 수 있다). CSV만 있다면 `data/`에 넣고 `build.py`의 TABS를 비워 둔다.
2. 스캐폴드를 실행한다. 탭 이름과 gid는 시트에서 자동으로 찾는다.

   ```bash
   python3 ~/.claude/skills/dashboard-scaffold/scripts/scaffold.py <대상폴더> --sheet-url "<URL>" --title "<대시보드 제목>"
   ```

   - 대상 폴더에 같은 이름의 파일이 이미 있으면 덮어쓰지 않고 건너뛴다(`--force`로만 덮어씀).
   - 탭을 직접 지정하려면 `--tabs "claim:123,patient:456"`.
3. `cd <대상폴더> && python3 build.py`로 데이터가 내려받아지고 `data/overview.json`이 생기는지 확인한다.
4. 만든 시트를 `docs/requirements.md`에 한 줄씩 정리하기 전에, 먼저 데이터를 파악해 사용자에게 요약해 준다(탭별 행 수, 조인 키, 기간, NULL이 많은 컬럼, 연결 안 되는 테이블).
5. 사용자가 구조에 동의하면 **요구사항 인터뷰**로 넘어간다. 아래 질문 틀을 `AskUserQuestion`으로 나눠 묻고 답을 `docs/requirements.md`에 기록한다.

## 통일 양식: 지표 하나 = 같은 이름 세 곳

| 어디서 | 규칙 | 예 |
|---|---|---|
| `build.py` | 함수 `metric_<이름>()` 이 dict/list 를 반환 | `metric_monthly_trend()` |
| `data/` | 자동으로 `<이름>.json` 으로 저장 | `monthly_trend.json` |
| `index.html` | `<section data-metric="<이름>">` 이 그 JSON 을 그림 | `data-metric="monthly_trend"` |

`build.py`는 `metric_` 로 시작하는 함수를 자동 수집하므로 등록 코드가 필요 없다. `index.html`은 `renderers.<이름>` 이 있으면 그것으로 그리고, 없으면 JSON 을 그대로 보여 준다. 그래서 지표 추가 = 함수 하나 + 섹션 하나 + (선택) 렌더러 하나다. 이 규칙이 있으면 파일이 커져도 어디를 고치면 되는지 헷갈리지 않는다.

## 성장 규칙 (불편해질 때만)

| 신호 | 다음 구조 |
|---|---|
| `build.py` 약 300줄 초과 | `metrics/` 폴더로 분리, 지표당 파일 하나, 파일명 = 지표명 |
| `index.html` 약 500줄 초과 | `style.css`, `app.js`로 분리 |
| 페이지가 2개 이상 필요 | `pages/` 또는 탭 구조 검토 |
| 데이터 갱신이 잦아짐 | 그때 Makefile 추가 |

분리할 때도 이름 규칙(지표명 = 함수명 = JSON명 = 섹션 id)은 유지한다.

## 요구사항 인터뷰 질문 틀

한 번에 1~4개씩, 데이터를 본 뒤 구체적인 선택지로 묻는다.

1. **누가, 무엇을 결정하려고 보는가** (보는 사람, 가장 먼저 답해야 할 질문 3개)
2. **핵심 지표(KPI)**: 어떤 숫자를 맨 위에 둘지, 정의가 모호한 것(예: 환자 수 = 청구에 등장한 고유 환자?)
3. **분석 축**: 시간(월/분기), 지역, 인구통계, 기관, 상품 등 어떤 쪼개기가 필요한지
4. **필터와 상호작용**: 기간·지역 필터가 필요한지, 클릭 시 드릴다운이 필요한지
5. **화면**: 한 페이지 스크롤인지 탭인지, 모바일 지원, 다크 모드
6. **배포**: 로컬로만 볼지, 정적 호스팅/Artifact로 공유할지, 갱신 주기
7. **데이터 한계**: 개인정보 민감도, 집계 시 숨겨야 할 소규모 셀

답은 `docs/requirements.md`에 "지표 목록(이름, 정의, 필요한 테이블, 차트 종류)" 표로 정리한다. 이 표의 이름이 그대로 지표명이 된다.

## 주의

- 시트 값이 모두 텍스트일 수 있다. 앞자리 0 코드는 문자열로 유지하고 금액·건수만 변환한다.
- 용량이 큰 원본(수만 행)은 브라우저로 직접 읽지 말고 `build.py`에서 집계한 JSON만 읽게 한다.
- 개인정보가 있을 수 있는 원본 CSV는 `.gitignore`에 들어 있다. 집계 JSON도 소규모 셀이 식별 가능하면 공개 전에 점검한다.
